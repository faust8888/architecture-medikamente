# 3) Автоматизированный контроль и реестр средств защиты

## 3.1. Автоматизированный контроль (что предложить по заданию)

### Контроль Encryption In Transit

- **Policy as Code**: проверка, что все входящие/исходящие endpoints используют TLS; запрет plaintext портов.
- **Service-to-service mTLS**: автоматическая выдача/ротация сертификатов (service mesh или PKI).
- **Контроль контрактов интеграций**: схемы/DTO с минимизацией (не допускать медданные в «не тех» доменах).
- **Сканирование конфигураций**: IaC/CI‑политики (например, запрет `http://`, проверка cipher suites).

### Контроль Encryption At Rest

- **Проверка настроек хранилищ**: «encryption=true» для БД/объектного хранилища/дисков.
- **KMS guardrails**: запрет использования не‑KMS ключей, запрет shared‑keys между доменами.
- **Автоматическая ротация ключей** по политике.
- **Контроль бэкапов**: шифрование и изоляция хранилищ бэкапов, периодические проверки восстановления.

### Контроль утечек и неправильного использования

- **DLP** на почте и в выгрузках: блокировать/карантинить `confidential_health` и `confidential_pii`.
- **Audit + SIEM**: алерты на массовые выборки/экспорт, доступ вне смены, нетипичные паттерны.
- **Data tagging enforcement**: новые поля/таблицы/топики должны иметь теги; PR‑гейт в CI (условие релиза).

## 3.2. Реестр программных и аппаратных средств защиты (пример для сдачи)

Ниже — реестр «классов средств». Он подходит для планирования закупок/внедрения без жёсткой привязки к конкретному вендору.

### Реестр (таблица)

| Категория средства | Где применяется | Что защищает | Зачем нужно | Примечания |
|---|---|---|---|---|
| **KMS / HSM** (аппаратное/программное) | ключи доменов, токенизация | ключи ENC@REST, токены | исключить хранение ключей рядом с данными, обеспечить ротацию/аудит | HSM предпочтителен для master‑keys |
| **TLS termination / PKI** | периметр, сервис‑к‑сервису | In Transit | обеспечить TLS/mTLS, управлять сертификатами | автоматическая ротация, короткий TTL |
| **Service Mesh** (опционально) | внутренняя сеть сервисов | In Transit | mTLS по умолчанию, политики, observability | снижает риск misconfig |
| **Disk/Volume Encryption** | серверы/виртуалки/кластеры | At Rest | защита при краже дисков/снапшотов | базовый слой, не заменяет KMS |
| **DB Encryption (TDE)** | БД доменов | At Rest | защита данных в БД | + separate keys per domain |
| **Object Storage SSE-KMS** | документы/сканы | At Rest | защита файлов, ACL, версии | важно для PHI |
| **Secrets Manager** | приложения/CI/CD | In Use | секреты, ротация | запрет секретов в коде |
| **DLP** | почта/порталы/экспорт | In Transit/экспорт | предотвращение утечек | политики по тегам |
| **SIEM** | безопасность | обнаружение атак/аномалий | корреляция, алерты | источники: audit, KMS logs, gateway logs |
| **Audit Logging Pipeline** | домены | расследуемость | кто/что/когда/зачем | WORM‑режим для критичных логов |
| **Endpoint Protection / MDM** | рабочие места/моб. | In Use | защита от копирования/малвари | важно для персонала |

## 3.3. Итоговая таблица из задания (пример формата)

| Данные | В чём необходимость защиты | Инструменты защиты |
|---|---|---|
| Медкарта, диагнозы, назначения (`Confidential‑Health`) | максимальный ущерб при утечке; медтайна; риск неправомерного доступа | ENC@REST (DB+storage) + KMS/HSM, TLS/mTLS, RBAC/ABAC, audit+SIEM, DLP |
| Результаты анализов (`Confidential‑Health`) | PHI + интеграция с партнёром → повышенный риск канала | mTLS + контракт минимизации, ENC@REST, object storage SSE‑KMS, audit |
| ПДн пациента (ФИО, контакты) (`Confidential‑PII`) | фрод/социнж; регуляторные риски | ENC@REST, TLS, маскирование в UI, DLP, audit |
| Платежи/договоры (`Confidential‑Finance`) | фрод/споры; важна целостность | ENC@REST, TLS, неизменяемые audit‑логи, сегментация доступа |
| Документы/сканы (PDF/JPG) | обычно содержат PHI/PII; легко копируются | object storage SSE‑KMS, ACL по объектам, ссылки вместо вложений, DLP |
| Бэкапы | содержат «всё»; типичная цель атак | ENC@REST отдельными ключами, изоляция доступа, контроль восстановления |
| Аудит‑логи доступа | расследуемость и детект атак | ENC@REST, WORM/immutability, SIEM‑корреляция, контроль целостности |
