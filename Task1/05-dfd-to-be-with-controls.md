# 5) DFD — To‑Be (с контрольными мерами на потоках)

Ниже — целевое представление потоков данных с отмеченными контрольными мерами. Диаграммы соответствуют процессам из `02-dfd-as-is.md`, но показывают «как должно быть», чтобы обеспечить конфиденциальность и управляемость данных.

Обозначения контролей (сокращения на диаграммах):
- **TLS** — шифрование в транзите
- **ENC@REST** — шифрование на хранении
- **RBAC/ABAC** — разграничение доступа по ролям/атрибутам
- **MASK** — маскирование/обфускация в UI/выгрузках
- **AUDIT** — аудит доступа к данным (кто/что/когда/зачем)
- **DLP** — предотвращение утечек (почта/файлы/экспорт)
- **TAG** — тегирование/классификация данных
- **KMS** — управление ключами шифрования

## DFD‑T1. Запись на приём (портал/ресепшен) — домен Appointments

```mermaid
flowchart LR
  P[Пациент] -->|Запрос записи (минимум PII)| API[API Gateway / BFF]
  API -->|TLS + AuthN| IAM[(IAM/SSO + MFA)]
  API -->|Create/Read appointment| A((Appointments Service))
  A -->|ENC@REST + TAG + AUDIT| ADS[(Appointments DB)]
  R[Ресепшен] -->|Работа в портале| API
  A -->|Событие: appointment.created (минимизация)| BUS[(Event Bus)]
  BUS -->|Уведомления| N((Notifications Service))
  N -->|DLP + шаблоны без лишних данных| MSG[Email/SMS/Push]
```

Ключевые изменения:
- данные записи больше не живут в Excel;
- минимизация раскрытия: в уведомлениях — минимум PII;
- аудит и теги на уровне сущностей.

## DFD‑T2. Медицинская карта — домен EMR (строго ограниченный контур)

```mermaid
flowchart LR
  D[Врач] -->|Работа в EMR UI| API2[EMR API]
  API2 -->|TLS + AuthZ (RBAC/ABAC)| IAM[(IAM/SSO + MFA)]
  API2 -->|CRUD медкарты| EMR((EMR Service))
  EMR -->|ENC@REST + KMS| EMRDB[(EMR DB)]
  EMRDB -->|TAG: confidential_health| CAT[(Data Catalog/Tags)]
  EMR -->|AUDIT (read/write/export)| LOG[(Audit Log)]
  LOG --> SIEM[(SIEM/Alerting)]
```

Ключевые изменения:
- медданные отделены от домена записи/расписаний;
- доступ врача контролируется отношением к пациенту/филиалу/контексту (ABAC);
- все обращения к `confidential_health` аудируются.

## DFD‑T3. Анализы — интеграция с лабораторией через контрактное API (минимизация)

```mermaid
flowchart LR
  L[Лаборатория] -->|TLS + mTLS + контракт (минимум)| LABAPI[Lab Integration API]
  LABAPI -->|Валидация + TAG| LAB((Lab Service))
  LAB -->|ENC@REST| LABDB[(Lab DB)]
  LAB -->|Документы/файлы (ENC@REST)| OBJ[(Object Storage)]
  LAB -->|AUDIT| LOG[(Audit Log)]
  D[Врач] -->|Запрос результатов (RBAC/ABAC)| API2[EMR API]
  API2 --> LAB
```

Ключевые изменения:
- уход от почты как канала передачи медданных;
- контрактный обмен с минимизацией полей;
- файлы анализов — в объектном хранилище с ACL/аудитом, не в общих папках.

## DFD‑T4. Платежи — отдельный домен Billing (минимизация, разделение от EMR)

```mermaid
flowchart LR
  C[Кассир] -->|Портал/терминал| BILLAPI[Billing API]
  BILLAPI -->|AuthZ RBAC/ABAC + MASK| BILL((Billing Service))
  BILL -->|ENC@REST + TAG| BILLDB[(Billing DB)]
  BILL -->|Интеграция с фискализацией| K[ККМ/Фискальный провайдер]
  BILL -->|AUDIT| LOG[(Audit Log)]
```

Ключевые изменения:
- биллинг не получает медицинские данные (Data Minimization);
- маскирование и ограничение полей для ролей.

## DFD‑T5. Обмен файлами и коммуникации — запрет «общих папок» для чувствительных данных

```mermaid
flowchart LR
  U[Сотрудник] -->|Загрузка документа| DOC((Document Service))
  DOC -->|ENC@REST + KMS + TAG| OBJ[(Object Storage)]
  DOC -->|AUDIT| LOG[(Audit Log)]
  DOC -->|Ссылка (не вложение)| N((Notifications))
  N -->|DLP| MSG[Email/SMS/Push]
```

Ключевые изменения:
- документы не пересылаются вложениями, передаются ссылками с контролем доступа;
- DLP и теги снижают риск утечек.

## Контрольные точки, которые должны присутствовать «по умолчанию»

- **На входе (API)**: AuthN/AuthZ, минимизация полей, валидация контрактов.
- **В сервисах**: проверки RBAC/ABAC на каждую операцию с чувствительными сущностями.
- **В хранилищах**: ENC@REST + управление ключами (KMS), теги на сущностях/полях.
- **В наблюдаемости**: AUDIT событий доступа/экспорта + алерты по аномалиям.
- **В коммуникациях**: DLP, запрет вложений с `confidential_*`, ссылки с ограниченным доступом.
